## Reconciled product contract

1. **One effect model.** The UI Effects section has Effect options `Off` and `Tactile`, the short helper text `Affects Secondary buttons and surface-style Tabs.`, and the existing shared Strength control. Remove both independent target toggles; do not relocate them or add another target configuration. Off is flat and makes Strength semantically disabled and visually de-emphasized. Tactile makes Strength active. Strength remains an integer from 0 through 100 and is retained when switching Off, so a later Tactile selection restores the selected intensity. Absence resolves to Off at the existing default strength. Explicit canonical default and absence compare equally for dirty/history purposes.
2. **Theme v3 migration.** Keep `schemaVersion: "3.0"` and one optional strict `uiEffects` value. Canonical new persisted/exported values contain only `effect: "off" | "tactile"` and `strength` as the accepted typed token leaves. Exact previously accepted four-field Theme v3 values (`effect: "tactile"`, `outlineButtons`, `tabs`, `strength`) import safely: either prior target true maps to Tactile; both false maps to Off; strength and all unrelated theme data are preserved. Older v1/v2/v3 themes without UI Effects remain visually flat. Normalize at all accepted Theme v3 ingress paths, including direct schema validation and Workbench saved-theme load, before the strict canonical shape is enforced; do not silently drop malformed fields. Newly exported themes use the two-field canonical shape. No Theme v4, alternate theme format, or generalized material/effects framework.
3. **Closed mutation.** Keep exactly 13 operations, their names and order, including one `setUiEffects`; do not add an operation or raw style/path target. Its new canonical payload contains only `effect` and `strength`. The exact prior four-field `setUiEffects` payload is admitted at its validation boundary and normalized by the same any-target rule, preserving prior callers without accepting mixed/partial/unknown fields. Maintain bounded strength, strict validation, revision/base identity, atomic rejection, proposal/Design Command boundaries, history, Undo/Redo/Reset, dirty state, save/reload and import/export. Update capability descriptions and meaningful tests to reflect the canonical shape. A mutation protocol version or public API change beyond this narrow compatibility bridge requires evidence and a new owner decision.
4. **Target and visual semantics.** Tactile applies automatically to Secondary Buttons and active surface/pill Tabs only. Default/primary, Outline, destructive, ghost, link, line/minimal Tabs, Inputs and all other primitives remain flat. Outline returns to its normal accepted border/background behavior. Secondary retains its filled semantic surface. Secondary and selected surface Tabs share one token-driven light/dark recipe, same Strength mapping, soft internal illumination, restrained depth and subtle translucent semantic edge/ring rather than an Outline-style hard border. Tune the exact visual treatment through browser evidence; do not hard-code raw mode colors or introduce heavy bevel/gloss/shadow. Preserve Button and Tabs sizing, type, radius, icon, keyboard, focus-visible, disabled and selected semantics. Secondary Button composition through accepted `asChild` triggers must receive the same effect without matching unrelated components.
5. **Workbench Tabs and specimens.** Left Colors/Typography/Geometry/Effects/Command and right Cards/Design system/App shells/States lists use the accepted default shadcn surface Tabs. Preserve labels, order, location, state, keyboard/focus behavior and scroll containment. Lists follow content width; triggers follow natural width, with no full-width list or equal-width trigger stretch. Off yields normal flat surface Tabs; Tactile styles only the active trigger through the shared effect. Add `Manage storage` as a Secondary Button below Storage content with no workflow, state, navigation or network. Convert compact collapsible section triggers to Secondary visual treatment while preserving measured height, width behavior, padding, font size/weight/case, chevron size, gap, radius, alignment, placement, collapse and keyboard semantics. Convert Create account GitHub and Google Buttons to Secondary, preserving two-column geometry, icons, labels, focus and no OAuth behavior. All these specimens inherit the shared effect automatically; no local tactile recipes.
6. **Design system Colors preview only.** Keep the two-column rectangular swatches and make them modestly narrower. Per-color labels use the same text size as HEX, uppercase normal readable weight and base foreground semantic color; HEX stays visually secondary. Semantic group headings use title case, base foreground and one typography step larger. `Colors` and `Type scale` section headings increase one typography step. Increase inter-group spacing slightly without loosening each pair. In this preview only, map `sidebar`/`sidebar-foreground` to Background/Foreground, `sidebar-primary` pair to Primary Background/Primary Foreground, `sidebar-accent` pair to Accent Background/Accent Foreground, and `sidebar-border`/`sidebar-ring` to Sidebar Border/Sidebar Ring. Avoid duplicate screen-reader qualifiers after labels become contextual. Preserve live HEX values, light/dark, Sidebar token off/on aliases and dedicated values, responsive containment, group order and flat reference-sheet structure. Actual token keys, CSS variables, editor labels, aliases, schema and import/export keys do not change from PUI-122.
