## 1. Theme v3 semantic typography (PUI-63)

### Schema

Canonical `personal-ui-theme` v3: `schemaVersion: "3.0"`, `$schema: https://personal-ui.local/schema/theme-3.json`.

```text
typography.heading.font      fontFamily stack (1–16 names, closed font-name grammar)
typography.heading.weight    { $type: "fontWeight", $value: integer 100–900, multiple of 100 }
typography.heading.tracking  { $type: "dimension", $value: em from -0.25em to 0.25em }
typography.body.font / weight / tracking   (same shapes)
typography.mono              fontFamily stack (a font primitive, not a third role)
```

There is no parallel canonical `sans`/`serif`/`tracking` model: `typography` is a strict object with exactly
`heading`, `body`, `mono`. Font size and line height are not theme data. v2.0 and v2.1 are frozen input-only schemas
(`themeV2_0Schema`, `themeV2_1Schema`, URI `theme-2.json`); v1 stays as before.

### Migration (exact, deterministic)

`validateTheme` accepts `1.0`, `2.0`, `2.1`, and `3.0` and returns canonical v3, validating each input against its own
frozen schema and each declared step (v1 → v2.0 → v2.1 → v3), so a value a later version cannot represent is reported
at its legacy path, never dropped. The v2.1 → v3 step (`migrateThemeV2_1`, `V3_MIGRATION_DEFAULTS`):

| v2.x | v3 |
| --- | --- |
| `serif` | `heading.font` |
| `sans` | `body.font` |
| `mono` | `mono` |
| `tracking` | `heading.tracking` and `body.tracking` |
| — | `heading.weight` = 600 (the `font-semibold` every v2 title rendered) |
| — | `body.weight` = 400 (CSS `normal`) |

All three stacks survive. Identity, revision, all 32 colours per mode (including the dedicated Sidebar set),
`sidebar.useDedicatedTokens`, `dedicatedValuesInitialized`, radius, space/density, shadows, motion, and
`$extensions` are carried unchanged. Persistence keeps the storage key `personal-ui-workbench/v1` and its
`themes`/`activeId`/`bases` shape; saved v1/v2.0/v2.1 custom themes migrate on read with selection and base records
intact, and the next Save writes v3.

Built-ins: `packages/core/src/theme/fixtures/default.json` is now a canonical v3 fixture (converted by exactly this
mapping; every non-typography value is byte-equal to the v2.1 fixture, asserted by the scan). Quiet Editorial's
committed source remains the historical v1 file `fixtures/valid.json` (it is the v1 migration fixture used across the
suites and context provenance) and loads as a complete canonical v3 theme through the declared chain. See risk R1.

### Renderer / exporter contract

`renderShadcnTailwindCss` (the sole renderer) emits in `:root`:

```css
--font-heading: <stack>;  --font-body: <stack>;  --font-mono: <stack>;
--font-weight-heading: 600;  --font-weight-body: 400;
--tracking-heading: 0em;  --tracking-body: 0em;
```

then composed roles and the document Body rule:

```css
@utility type-heading { font-family: var(--font-heading); font-weight: var(--font-weight-heading); letter-spacing: var(--tracking-heading); }
@utility type-body    { font-family: var(--font-body);    font-weight: var(--font-weight-body);    letter-spacing: var(--tracking-body); }
@layer base { body { font-family: var(--font-body); font-weight: var(--font-weight-body); letter-spacing: var(--tracking-body); } }
```

- Namespaces: `font-*` primitives, `tracking-*` role tracking, `type-*` composed roles, `text-*` untouched Tailwind
  size/colour. No `text-heading`/`text-body`, no size or line-height variables.
- Role primitives are plain runtime `:root` properties, never `@theme` entries, so they create no competing
  `font-*`/`tracking-*` utilities and stay live in the preview iframe. Tailwind 4.3.3's own `font-mono` utility compiles
  to `font-family: var(--font-mono)` and preflight's code/pre default reads `--font-mono`, so code follows the theme's
  mono stack (verified in the compiled Workbench CSS).
- The retired `--font-family-{sans,serif,mono}`, `--tracking-base`, and `@theme` `--font-sans/--font-serif/--font-mono/
  --tracking-normal` entries are gone; `font-sans`/`font-serif` revert to Tailwind defaults and nothing in the product
  uses them.
- Goldens `fixtures/default.css` and `fixtures/quiet-editorial.css` were regenerated from the renderer.

  (Font). The old *Font families* and standalone tracking (*Spacing*) groups are gone. Heading and Body pick from the

## 2. Session-local history and recovery (PUI-3)

Pure model in `apps/workbench/src/history.ts`; wiring in `App.tsx` and `LiveControls.tsx`.

- One track per theme id (`past`/`future` snapshots of design content), in React state/refs only: never persisted,
  never canonical data, never an operation. Reload clears everything. Tracks are bounded to 100 checkpoints (oldest
  dropped deterministically).
- Undo / Redo / Reset rebuild the snapshot's content under the current identity at `revision + 1` and revalidate it
  through `themeSchema`, so revisions only increase and proposal stale protection stays sound.
- No-op edits and invalid drafts create no history. A committed edit after Undo clears Redo.
- Dirty = any token-value difference from the durable baseline (`diffThemeTokens`), ignoring revision, identity, and
  Sidebar initialization bookkeeping. `data-theme-status` now uses it, so undoing back to the baseline is clean.
- Coalescing: a gesture key per control. Slider drags (pointer down→up) and each keyboard step are one gesture; one
  focus session of a numeric/colour text draft or a native colour-picker session is one gesture. Every step is rebuilt
  from the gesture's captured base, so the preview is live but the revision advances once, and one checkpoint is
  recorded when the gesture ends (blur, slider commit, or any other control/action). Radix reports a keyboard commit
  before its value change, so the slider closes its gesture in a microtask. Font, switch, and Design Command changes
  are single commits.
- Toolbar: a compact `role="group"` "Edit history" with ghost icon buttons **Undo**, **Redo**, **Reset** (Lucide
  `Undo2`, `Redo2`, `RotateCcw` from the already-pinned `lucide-react`) immediately before Export JSON and Save. Each
  has an accessible name and title; Undo/Redo disable on empty stacks, Reset when clean; all three disable while a
  proposal is staged or a command is evaluating. Below 640px, Export JSON and Save become icon-only (their accessible
  names and titles unchanged) so the 390px toolbar fits without overflow.
- Reset opens the accepted Responsive Dialog/Drawer confirmation ("Reset <theme>?", Reset theme / Cancel). Built-ins
  reset to the immutable canonical fixture; custom themes to the last saved snapshot. Reset is one undoable
  transition and posts a notice.
- Lifecycle: switching themes stores the leaving theme's working state and restores the target's (its history track
  is keyed by id, so it is preserved too). Custom Save re-baselines without clearing history; Undo after Save makes the
  theme dirty again. Save As selects the new custom theme with a clean track and returns the source built-in to its
  fixture with a clean track. Deleting a custom theme drops its working state and track and falls back to Default's
  in-session working state (or the fixture). Design Command Preview and Discard record nothing; Apply records one
  checkpoint after normal proposal validation.
